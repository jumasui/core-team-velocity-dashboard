Human review rounds

Each measured round starts with a human or team review request and ends at the next formal review from a human other than the author. Additional requests before that response share one round.

Bot reviews are excluded. Draft, closure or request-removal interruptions and requests without a response remain unmeasured. This is elapsed waiting time, not active review effort. Reviews without an observed request have no measured round.

Coverage and definitions

How to interpret this snapshot

The board’s current filter and column mapping are applied retrospectively. Full lifetime status histories are retained for older tickets. Completion is the latest entry from a non-Done status into the board’s Done column for tickets currently Done. Reopened tickets retain repeat visits.

Time charts require Done at the original cutoff and a completion during the study year, including older carried-in tickets. All resolutions qualify; Done does not imply shipped code. The completion-rate denominator instead uses tickets created during the study year. Its numerator includes reopened tickets that previously reached Done.

Title Jira keys and explicit Jira-side PR URLs are included associations. PR charts require direct associations to qualifying Done Jiras. Dependency links inform ownership but do not add PRs to those charts. Body-only mentions remain candidates. Missing associations and inaccessible repos limit PR comparisons.

The benchmark is AISTUDIO excluding every saved board 4073 issue key. It uses the same snapshot cutoff and type, ownership, search and PR filters. A PR linked to both board and non-board Done Jiras may appear in both cohorts. Workflow milestones absent from other teams remain unmeasured.

Default issue types exclude epics and subtasks to reduce parent/child double counting. Release-port detection uses explicit cherry-pick/backport/CP wording and may miss unmarked ports. Merge time is distinct from closed-unmerged time.
